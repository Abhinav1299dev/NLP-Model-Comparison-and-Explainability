# Data — Member 2

No corpus text is stored in this repository. All data is regenerated by the
scripts below and kept out of git (see `.gitignore`).

## Final source: Charak Samhita New Edition

| Item | Value |
|---|---|
| Publisher | Charak Samhita Research, Training and Skill Development Centre |
| Location | `https://www.carakasamhitaonline.com/index.php?title=<Chapter>` |
| Content used | English translation paragraphs of **Nidana Sthana** and **Chikitsa Sthana** chapters (section *"Sanskrit Text, Transliteration and English Translation"*) |
| Content excluded | Devanagari and transliterated verses; modern commentary sections (*Tattva Vimarsha*, *Vidhi Vimarsha*, research tables) |
| Provenance kept | sthana, chapter number, page title, topic heading, verse reference (e.g. `12-15`), URL with revision id, chapter DOI, licence |
| Licence | **CC BY-NC-SA 4.0** (stated in every page footer) — attribution required, non-commercial use only, derived datasets under the same licence |

Why this source: it is verse-referenced, chapter-level DOIs are provided, the
licence is explicit, and it gives an English translation aligned to the
Sanskrit verses — which matters because PubMedBERT is an English model.

### Build

```bash
python -m training.corpus_charaka --out data/processed/charaka_units.jsonl   # downloads + caches pages (≈1 s/page)
python -m training.build_dataset --units data/processed/charaka_units.jsonl  # candidates + review sheet
```

`charaka_units.manifest.json` records the SHA-256 of the units file, the chapters
found and the retrieval date. Quote these in the report.

Chapter pages are discovered from the `Nidana_Sthana` and `Chikitsa_Sthana`
index pages and kept only if the page itself states
"Nidana/Chikitsa Sthana Chapter n". If the site layout changes, the parser
returns zero units and the script stops with an error instead of producing a
partial corpus silently.

## Originally proposed source: `shinigamiRaj/IndianVedasOriginal`

Not used unless it passes `python -m training.inspect_hf_candidate`. The check
requires Charaka Samhita to be identified by **metadata** (not by keyword hits in
the text body), predominantly English text, chapter/verse references and a
declared licence. In the environment where this delivery was prepared the
Hugging Face Hub was not reachable, so this inspection has **not** been run.
Public information found about the same author's model ("IndicVedas") describes
the underlying corpus as Vedas in Griffith translations and bilingual
Sanskrit/Hindi, with "structural chapters" for Ayurvedic works; that does not
establish an English, verse-referenced Charaka Samhita text. Run the inspection
before considering this dataset.

## Label provenance

| `label_origin` | Meaning | Used for training | Used as reported accuracy |
|---|---|---|---|
| `weak_positive` | rule: trigger bound between the two entities in one clause | yes | no |
| `weak_negative` | rule: sentence has no relational/causal language | yes | no |
| `uncertain` | rule could not decide (incl. causal statements) | no | no |
| `gold` | manually reviewed and adjudicated | yes | **yes** |

## Annotation guideline (short form)

* Label the relation **stated in the sentence**, not what is known elsewhere.
* `TREATS`: herb/formulation → disease or symptom it is said to cure, alleviate or be indicated for.
* `REDUCES`: herb/formulation/diet → dosha it pacifies or alleviates.
* `AGGRAVATES`: herb/formulation/diet → dosha it increases or vitiates.
* `HAS_PROPERTY`: herb → its rasa, guna, virya or vipaka value.
* `NO_RELATION`: the sentence does not state any of the above between the two marked entities (including causal statements such as "X causes kushtha", which the team schema cannot express — add a `review_note`).
* Check the entity type of ambiguous terms (e.g. *kushtha* as disease vs. the herb *Saussurea*).
* Two reviewers per item for the test chapters; report Cohen's κ.
